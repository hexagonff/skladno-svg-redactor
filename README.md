# Складно

Веб-сервис для сборки векторных композиций из готовых SVG-иллюстраций. Пользователь описывает идею или перечисляет нужные предметы, а сервис подбирает объекты из библиотеки и размещает их на холсте. Результат можно отредактировать и скачать в SVG.

ИИ выбирает существующие объекты, их роли и детализацию. Новую графику он не генерирует и исходные контуры не перерисовывает.

## Возможности

- Автоматическая сборка по метафоре, заголовку или названиям компонентов.
- Встроенная библиотека: 10 объектов и 3 фона, каждый в двух вариантах детализации L/S.
- Загрузка собственных SVG с автоматическим подбором цветов под текущую палитру.
- Перемещение мышью и пальцем, пропорциональное масштабирование за углы или через поля ширины и высоты, поворот с шагом 15°.
- Дублирование всех настроек объекта: копия появляется с небольшим сдвигом, сразу над оригиналом, и выделяется.
- Управление слоями через список, перетаскивание, стрелки и числовое поле.
- Независимый выбор фона, его детализации и цветовой палитры.
- Главные и фоновые объекты, индивидуальная замена цветов и создание своих палитр.
- Экспорт самостоятельного SVG с отдельными объектами и векторными контурами.

## Локальный запуск

Потребуются Node.js 22.13+ из ветки 22.x и npm. Полный список поддерживаемых версий Node указан в поле `engines` файла `package.json`.

1. Установите зависимости из корня проекта:

   ```sh
   npm ci
   ```

2. Скопируйте `.env.example` в `.env.local` и укажите свой ключ OpenRouter:

   ```dotenv
   OPENROUTER_API_KEY=your-openrouter-api-key
   OPENROUTER_MODEL=dots-studio/dots-3-note-preview:free
   ```

   `dots-studio/dots-3-note-preview:free` здесь — пример явно выбранной модели. Можно указать другой доступный идентификатор с суффиксом `:free`. Платные модели текущая серверная функция отклоняет. Если `OPENROUTER_MODEL` не задана, используется `DEFAULT_COMPOSITION_MODEL` из `api/compose.ts`.

3. Запустите приложение:

   ```sh
   npm run dev
   ```

4. Откройте адрес из терминала, обычно `http://localhost:5173`.

Сервер разработки Vite обслуживает и интерфейс, и локальный `/api/compose`. Отдельно запускать API не нужно. После изменения `.env.local` перезапустите сервер разработки.

Без ключа доступны ручная сборка, импорт SVG, настройка палитры и экспорт. Для автоматической сборки по описанию нужны настроенный OpenRouter и подключение к интернету. Доступность моделей и квоты определяет провайдер.

### Переменные окружения

| Переменная             | Назначение                                                          |
| ---------------------- | ------------------------------------------------------------------- |
| `OPENROUTER_API_KEY`   | Серверный ключ для запросов к OpenRouter. Обязателен для ИИ-сборки. |
| `OPENROUTER_MODEL`     | Модель: `dots-studio/dots-3-note-preview:free` или идентификатор с суффиксом `:free`.    |
| `OPENROUTER_SITE_URL`  | Необязательный адрес приложения для атрибуции запросов OpenRouter.  |
| `OPENROUTER_SITE_NAME` | Необязательное имя приложения для атрибуции запросов OpenRouter.    |

Ключ читает только серверная функция. Он не передаётся браузеру. Не добавляйте к его имени префикс `VITE_` и не помещайте секрет в клиентский код. Файлы `.env` и `.env.*` исключены из Git, кроме шаблона `.env.example` без ключа.

## Как пользоваться

1. В блоке «Собрать по описанию» введите идею или названия предметов и нажмите «Собрать композицию». Либо добавьте объекты вручную из библиотеки.
2. Выберите фон, детализацию фона и палитру в настройках.
3. Выделите объект на холсте или в списке слоёв. Измените его размер, детализацию L/S, роль, цвета и положение. Быстрые кнопки над выделением позволяют менять слой, поворачивать, дублировать и удалять объект.
4. При необходимости загрузите свой SVG кнопкой «Загрузить SVG». После загрузки нажмите на новый элемент библиотеки, чтобы добавить его на холст.
5. Нажмите «Скачать SVG», чтобы сохранить результат.

Новая ИИ-композиция заменяет объекты на холсте, сохраняя выбранные фон, детализацию фона и палитру. Неудачный запрос или отмена сборки не заменяют текущую композицию.

### Примеры запросов

| Сценарий                 | Запрос                           |
| ------------------------ | -------------------------------- |
| Метафора или заголовок   | «Готовлюсь к экзамену»           |
| Перечисление компонентов | «Книга, лампа, ручка и наушники» |
| Тематическая композиция  | «Планирование личного бюджета»   |

ИИ подбирает предметы только из доступного каталога. Если обязательного предмета в нём нет, сервис сообщает об ограничении.

## Как работает сборка

1. Клиент отправляет на `POST /api/compose` текст запроса и описание каталога: идентификаторы, названия, смысловые описания и доступные варианты L/S. Содержимое SVG в запрос не входит. Для загруженных объектов смысловой подбор опирается на название файла, а не на распознавание изображения.
2. Сервер передаёт запрос модели через OpenRouter. В ответ принимается только JSON-план: существующие идентификаторы объектов, роли `main`/`bg`, детализация L/S и короткое объяснение.
3. Формат и состав плана проверяются через zod и каталог. Неизвестные объекты, недоступная детализация, повторяющиеся идентификаторы и посторонние поля отклоняются.
4. Алгоритм раскладки перебирает порядок объектов и размещение строками или столбцами. Он учитывает реальные размеры выбранных SVG, отступы и промежутки, затем выбирает сбалансированный вариант, который помещается в холст. Пропорции и стандартный масштаб объектов сохраняются. Если подходящей раскладки нет, текущая сцена остаётся без изменений.
5. Фоновые объекты размещаются ниже главных. Общий SVG-рендерер собирает результат для экрана и скачивания.

Координаты, масштаб и цвета рассчитывает код приложения. Модель не получает API-ключ в тексте запроса и не управляет геометрией.

## Библиотека, цвета и повторное использование SVG

Исходные файлы библиотеки находятся в `src/assets/library` и названы по схеме `<id>__L.svg` / `<id>__S.svg`. Это отдельные исходники с разной детализацией: S не получается простым уменьшением L. При переключении сохраняется видимая ширина объекта и собственные пропорции выбранного исходника.

Команда `npm run build:library` подготавливает SVG, переводит цвета в роли палитры, создаёт фоновые варианты объектов и записывает `manifest.json`. Исходные SVG она не изменяет. Манифест загружается браузером как отдельный статический файл. Нужный объект извлекается по идентификатору и детализации.

Каждый экземпляр на холсте хранит ссылку на объект каталога и свои настройки: положение, масштаб, угол, роль, детализацию и замены цветов. Один исходный SVG можно использовать многократно. При рендеринге внутренние ID и ссылки получают префикс экземпляра, чтобы копии не конфликтовали.

Цветовые схемы описаны в `src/assets/schemes.json`, исходные карты цветов — в `src/assets/color-map.json`. Превью, холст и экспорт используют один механизм перекраски:

- `main` — главный объект, использующий цвета объектной и фоновой групп палитры;
- `bg` — фоновый объект, использующий только `bg1`, `bg2` и `bg3`;
- подложка холста выбирается отдельно от роли объектов;
- пользовательская палитра задаётся восемью HEX-значениями через поля или цветовые пикеры и перекрашивает всю сцену;
- индивидуальные замены цветов хранятся по ролям, поэтому сохраняются при смене палитры. Настройки главного и фонового вариантов объекта независимы.

### Импорт своих объектов

Принимаются файлы `.svg` до 2 МБ со статическими контурами, фигурами, группами и внутренними `clipPath`. Проверка выполняется до вставки графики в страницу. Цвета нормализуются и автоматически сопоставляются с текущей палитрой; если цветных оттенков больше, чем доступных ролей, часть оттенков объединяется с сообщением пользователю.

Растр, текст, градиенты, фильтры, `use`, скрипты, обработчики событий, внешние ресурсы, `foreignObject` и глобальные `style` не поддерживаются. Допустимые inline-стили переводятся в атрибуты, служебные метаданные редакторов удаляются. Загруженный объект получает вариант L; отдельный S автоматически не создаётся.

## Экспорт и хранение данных

Экспорт содержит отдельные группы объектов, исходную векторную геометрию и преобразования. Цвета записываются непосредственно в SVG. Растровых вставок, внешних ресурсов, `foreignObject`, глобальных `style`, рамок выделения и кнопок редактора в результате нет. Масштабирование равномерное, порядок SVG-элементов соответствует слоям композиции.

Сцена, загруженные объекты и пользовательские палитры хранятся только в памяти вкладки. База данных, localStorage, sessionStorage и IndexedDB для них не используются. После перезагрузки страницы изменения теряются, поэтому готовый результат нужно скачать заранее. Сам SVG-файл пользователя на сервер не загружается; OpenRouter получает текст запроса и метаданные каталога.

## Ограничения текущей версии

- Холст квадратный, 1000 × 1000. Выбора горизонтального или вертикального формата нет.
- ИИ-сборка принимает запрос до 1000 символов, выбирает до 6 разных объектов и поддерживает каталог до 100 записей. Ручное добавление и дублирование не ограничены шестью объектами.
- Автоматическая раскладка сохраняет стандартный размер объектов; если они не помещаются, нужно выбрать меньше предметов. После сборки размер можно изменить вручную.
- Палитра создаётся вручную; импорта файла палитры нет.
- Пакетный импорт библиотеки, редактирование отдельных контуров внутри приложения, undo/redo и восстановление проекта после перезагрузки не реализованы.
- Скачать композицию можно в SVG, но загрузки сохранённого SVG обратно как редактируемого проекта со всеми настройками сцены нет.
- Ручную проверку редактирования результата после импорта в Figma нужно выполнить отдельно. Проверка структуры SVG не заменяет проверку в самом редакторе.

## Команды и проверки

| Команда                 | Назначение                                                              |
| ----------------------- | ----------------------------------------------------------------------- |
| `npm run dev`           | Локальный запуск интерфейса и API через Vite.                           |
| `npm run build`         | Подготовка библиотеки, проверка TypeScript и сборка фронтенда в `dist`. |
| `npm run build:library` | Пересборка манифеста встроенных SVG.                                    |
| `npm test`              | Запуск модульных тестов Vitest.                                         |
| `npm run lint`          | Проверка ESLint и форматирования Prettier.                              |
| `npm run test:e2e`      | Браузерные проверки Playwright.                                         |

Файлы `*.test.ts` рядом с исходниками — постоянные тесты логики, сторов, SVG и API. Браузерные сценарии находятся в `tests/*.pw.ts`: они проверяют сборку, перемещение, масштабирование, поворот, слои, цвета, дублирование, импорт и экспорт. Ответы ИИ в автоматических тестах подменяются, реальные запросы OpenRouter не требуются.

Перед первым запуском браузерных тестов установите Chromium:

```sh
npx playwright install chromium
npm run test:e2e
```

Вместо него можно использовать установленный Google Chrome. В PowerShell:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'chrome'
npm run test:e2e
```

Playwright запускает Vite на порту 5173 или использует уже работающий сервер по адресу `http://127.0.0.1:5173`. Временные отчёты и снимки находятся в `test-results` и `playwright-report`; они исключены из Git и не входят в приложение.

## Развёртывание

Приложению нужны статический фронтенд и одна Node.js serverless-функция `api/compose.ts`. Функция экспортирует обработчик Node HTTP; хостинг должен поддерживать его развёртывание вместе с зависимостями.

1. Установите зависимости командой `npm ci`.
2. Задайте `OPENROUTER_API_KEY` и выбранную `OPENROUTER_MODEL` в серверных переменных окружения хостинга.
3. Выполните `npm run build`. Папка со статическими файлами — `dist`.
4. Разверните серверную функцию и направьте на неё `POST /api/compose` на том же домене, с которого открывается интерфейс.
5. Проверьте опубликованную версию: загрузку библиотеки, сборку по описанию, ручное редактирование и скачивание SVG.

Один статический `dist` позволяет открыть ручной редактор, но для ИИ-сборки нужен работающий API. Команда Vite `build` не упаковывает серверную функцию в `dist`; её разворачивает хостинг отдельно. Файлы `.env.local` не должны попадать в публичную папку.

## Стек и структура

Vite, React, TypeScript в strict-режиме, MobX, mobx-react-lite, zod, Vitest и Playwright. Обработка SVG использует `@xmldom/xmldom`.

```text
api/compose.ts            Серверная функция OpenRouter
scripts/                  Сборка библиотеки и локальное подключение API
src/assets/               SVG, манифест, палитры и карты исходных цветов
src/domain/               Чистые функции модели сцены, геометрии, цветов и валидации
src/services/ai/          Клиент запроса композиции
src/services/layout/      Автоматическая раскладка
src/services/svg/         Подготовка, импорт, перекраска и рендеринг SVG
src/stores/               MobX-состояние сцены, библиотеки и палитр
src/ui/                   React-интерфейс
tests/                    Браузерные сценарии Playwright
```

Доменная логика не зависит от React и MobX и проверяется модульными тестами.

## Использование ИИ

- **OpenAI Codex** использовался при разработке: для работы с кодом, написания тестов, проверок и документации.
- **Модель через OpenRouter** используется в приложении для смыслового подбора объектов, ролей и детализации. Конкретный идентификатор задаётся серверной переменной `OPENROUTER_MODEL`; `openrouter/free` маршрутизирует запрос к доступной бесплатной модели.
- Генерация изображений с помощью ИИ в приложении не используется. Результат собирается из готовой SVG-библиотеки и загруженных пользователем объектов.
