# План реализации конструктора композиций (React + MobX)

## 0. Как понимается задача

- В библиотеке 10 объектов (книга, телефон, пазл, монета, наушники, лампа, цветы, кошелёк, папка, ручка) в двух размерах (L и S), всего 20 иллюстраций.
- У каждого объекта два состояния: **главный** (цветной) и **фоновый** (монохром).
- Есть 3 цветовые схемы, их число будет расти.
- Правила цвета: цвета фонов можно использовать в объектах, цвета объектов в фонах нельзя.
- Менять можно композицию, состояние объекта и его цвет. Нельзя менять пропорции объектов относительно друг друга, внутренности объекта и нарушать цветовую схему.
- ИИ **ничего не рисует**, он только выбирает и расставляет готовые объекты. Результат должен быть векторным SVG.
- Формат: веб-сервис. Плагин Figma допустим, но в сдаче просят ссылку на работающий сервис, поэтому делаем веб.

### Что нужно сдать

- Ссылка на работающий сервис или запускаемый проект с короткой демонстрацией.

- 2–3 примера собранных композиций.

## 1. Что сделать до разработки

1. **Выгрузить ассеты из Figma** в SVG:
   - каждый объект отдельным файлом, в L и S;
   - единая схема имён, например `book__L__main.svg`, `book__S__main.svg`;
   - внутри не должно быть растра, масок с картинками и текста;
   - у всех файлов должен быть единый принцип масштаба и viewBox.
2. **Проверить, как устроены фоновые объекты.** Если фоновый объект это тот же SVG, перекрашенный в монохром, отдельные файлы не нужны, фон получается функцией перекраски. Если это отдельные компоненты, выгрузить и их.
3. **Снять палитры**: для каждой из 3 схем взять hex-коды из Figma по ролям (фон холста, 4 цвета объектов, 4 цвета фоновых объектов, чёрный, белый). Роли должны быть одинаковыми во всех схемах, иначе перекраска невозможна.
4. **Определить соответствие цветов в SVG ролям палитры.** Открыть SVG и выписать используемые hex. Составить таблицу «цвет в исходнике → роль».
5. **Выписать допустимые форматы холста** из примеров в Figma: квадрат, горизонталь, вертикаль, с точными размерами.
6. **Описать теги и синонимы** для каждого объекта на русском и английском (книга, дневник, блокнот, чтение, учёба и т. д.). Это основа подбора объектов по метафоре.
7. **Завести аккаунты и ключи:** API LLM, хостинг (Vercel или Netlify) с serverless-функциями, GitHub-репозиторий.
8. **Если есть возможность, уточнить у заказчика:** верна ли трактовка «20 иллюстраций = 10 объектов × 2 размера» и в каком формате ожидается загрузка библиотеки (папка, zip или отдельные файлы).

## 2. Архитектура

### Стек

- Vite, React, TypeScript, MobX, mobx-react-lite.
- Холст: inline SVG в React. Canvas-библиотеки (Konva, Fabric) не нужны, они ломают векторность экспорта.
- Ручки трансформации (перемещение, поворот, масштаб): `react-moveable` или собственные на pointer events.
- SVG: SVGO и DOM-парсер. Валидация ответа ИИ: zod.
- Тесты: Vitest, e2e: Playwright.
- Серверная часть: одна serverless-функция `/api/compose`, чтобы не светить ключ LLM в браузере.

### Слои приложения

1. **domain**: чистые типы и функции без React и MobX.
2. **stores**: MobX-сторы (состояние и действия).
3. **services**: перекраска, сериализация, раскладка, клиент ИИ.
4. **ui**: компоненты.

### Доменная модель

- `Asset`: id, название, теги, синонимы (RU/EN), варианты по размерам `{L, S}`, у каждого SVG-содержимое, viewBox, размеры.
- `ColorScheme`: id, название, словарь `роль → hex`. Роли: `canvasBg`, `obj1..obj4`, `bg1..bg4`, `black`, `white`.
- `SceneItem`: id, assetId, состояние (`main` или `bg`), x, y, scale (одно число, чтобы пропорции не нарушались), rotation, flipX, z-порядок, цветовые переопределения по ролям.
- `CanvasConfig`: формат (ширина и высота), размер (L или S), схема.
- `Composition`: `CanvasConfig` плюс список `SceneItem`.

### MobX-сторы

- `LibraryStore`: загруженные ассеты и загрузка новых файлов.
- `PaletteStore`: доступные схемы, активная схема, загрузка палитры.
- `CanvasStore`: формат, размер L/S.
- `SceneStore`: элементы сцены, выделение, дублирование, удаление, порядок слоёв, undo/redo.
- `AiStore`: промпт, статус запроса, варианты раскладки, ошибки.
- `ExportStore`: сборка и скачивание SVG.
- `RootStore`: объединяет всё и отдаётся через React context.

### Ключевые алгоритмы

**Перекраска.** При подготовке ассета каждый hex заменяется на токен роли (например `{{obj2}}`), список ролей сохраняется в манифесте. При рендере и экспорте токены заменяются реальными hex активной схемы. Так цвета на холсте и в экспортированном SVG совпадают. CSS-переменные в экспорте не использовать: Figma и Illustrator их плохо понимают.

**Правило цветов.** Для главного объекта в пикере доступны цвета объектов и фона. Для фонового только цвета фона. Если фоновый вариант производный, он получается заменой ролей `objN → bgN`.

**Общий модуль подготовки SVG.** Один и тот же код (SVGO, поиск цветов, замена на роли) используется и в build-скрипте для встроенной библиотеки, и в браузере для загрузки пользователем. Это закрывает требование «загружать свою библиотеку» без дублирования логики.

**Загрузка палитры.** Принимать JSON со словарём ролей или список hex в фиксированном порядке ролей. Для неизвестных SVG сопоставлять цвета с ролями по яркости и близости. Загрузка палитры добавляет новую `ColorScheme` и делает её активной, сцена перекрашивается автоматически.

**Раскладка (layout engine).** Детерминированный алгоритм, не ИИ:

- набор шаблонов по числу объектов и ориентации холста, слоты в нормализованных координатах;
- объекты могут пересекаться и обрезаться краем холста, как в примерах;
- порядок слоёв определяется глубиной в изометрии (чем ниже по Y, тем выше слой);
- есть seed, чтобы кнопка «ещё вариант» давала новые раскладки;
- фоновые объекты ставятся крупнее и дальше от центра.

**ИИ-слой.**

- *Сценарий 1 (метафора или заголовок):* serverless-функция отправляет в LLM каталог (id, теги, описание) и просит вернуть структурированный JSON: список id объектов, роль каждого (main или bg), рекомендуемую схему. Ответ валидируется через zod, неизвестные id отбрасываются. Раскладывает уже layout engine. Это гарантирует, что ИИ не создаёт новые объекты.
- *Сценарий 2 (названия компонентов):* локальный нечёткий поиск по названиям и синонимам. К LLM обращаться только если совпадение не найдено.
- Fallback без ключа: подбор по тегам, чтобы сервис не падал.

**Экспорт SVG.**

- Корневой `<svg>` с `viewBox` формата холста, фоновый `<rect>`, на каждый элемент группа `<g transform>` с внутренностями SVG.
- Все id внутри ассетов получают уникальный префикс, иначе возникают коллизии градиентов и clipPath.
- Обрезка по краю холста через `clipPath`.
- Никаких `<image>`, `<style>` с глобальными классами и `foreignObject`.
- Проверить результат открытием в Figma и Illustrator.

### Структура проекта

```
/api
  compose.ts            # serverless: вызов LLM
/scripts
  build-library.ts      # SVG -> манифест + токенизированные ассеты
/src
  domain/               # типы, правила цветов, форматы
  services/
    svg/                # prepare, recolor, serialize, ids
    layout/             # шаблоны слотов, генератор раскладок
    ai/                 # клиент, схемы zod, fallback-поиск
  stores/
  ui/
    canvas/             # SceneView, ItemView, Transformer
    panels/             # Library, Colors, Size, Layers, AI, Export
  assets/library/       # исходные SVG и manifest.json
AGENTS.md
README.md
```

## 3. Шаги реализации

1. **Каркас проекта:** Vite, TS, ESLint, Prettier, Vitest, структура папок, deploy-пайплайн на хостинг с самого начала.
2. **Пайплайн ассетов:** build-скрипт и общий модуль подготовки SVG, генерация манифеста, тесты на токенизацию цветов.
3. **Домен и сторы:** типы, `RootStore`, `LibraryStore`, `PaletteStore` со встроенными тремя схемами.
4. **Рендер холста:** отображение элементов, перекраска по схеме, переключение L и S.
5. **Редактор:** добавление из библиотеки, перемещение, поворот, масштаб с сохранением пропорций, дублирование, удаление, порядок слоёв, undo/redo.
6. **Цвета:** выбор схемы, переключение главный/фоновый, пикер цвета объекта с учётом правила фонов и объектов.
7. **Форматы холста:** пресеты размеров из Figma.
8. **Экспорт:** сборка SVG, уникальные id, проверка в Figma.
9. **Layout engine:** шаблоны, обрезка по краям, seed и кнопка «ещё вариант».
10. **ИИ:** serverless-функция, схема ответа, сценарии 1 и 2, fallback.
11. **Загрузка библиотеки и палитры пользователем:** drag-and-drop SVG или zip, загрузка JSON или списка hex, автоматическая перекраска.
12. **Качество:** юнит-тесты (перекраска, сериализация, раскладка), e2e на основной сценарий, обработка ошибок, состояния загрузки, доступность, адаптивность.
13. **Сдача:** README с описанием архитектуры (хранение, извлечение и пересборка SVG), список ИИ-инструментов, 2–3 экспортированные композиции как примеры, проверка, что ссылка и репозиторий открываются.

## 4. Как работать с Codex

- Положить в корень `AGENTS.md`: стек, структура папок, правила («ИИ не генерирует графику», «пропорции не меняются», «экспорт только векторный»), команды сборки и тестов.
- Давать задачи строго по шагам выше, по одному за раз, с критериями приёмки («тесты проходят, экспорт открывается в Figma»).
- Сначала просить писать чистые функции в `services` с тестами, и только потом подключать их к сторам и UI.
- Сохранять промпты и список использованных ИИ-инструментов по ходу работы, чтобы не восстанавливать их для сдачи.

## 5. На что обратить внимание

- Коллизии id внутри SVG при вставке нескольких объектов на один холст.
- Объекты из Figma могут содержать градиенты и обводки, перекраска должна их учитывать.
- Единый принцип viewBox у всех ассетов, иначе масштаб и привязка поедут.
- Оценивают качество решений и рабочий результат, а не количество функций, поэтому лучше сделать меньше, но надёжно.
