# План реализации конструктора SVG-композиций

## 1. Цель и требования

Разработать веб-сервис, который автоматически собирает композиции из готовых SVG-объектов. Исходное ТЗ допускает также плагин Figma, но для этого проекта выбран веб-сервис.

Два обязательных сценария:

1. Пользователь вводит метафору или заголовок. Сервис подбирает подходящие объекты из каталога и собирает композицию.
2. Пользователь вводит названия нужных компонентов. Сервис находит их в каталоге и автоматически компонует.

Общие ограничения:

- ИИ выбирает только существующие `assetId`, роли `main`/`bg` и доступную детализацию L/S каждого объекта. Доступные варианты передаются в `availableSizes`; выбранный исходный SVG используется без изменения контуров. Координаты, поворот и цвета рассчитывает код. ИИ-сборка использует только исходные размеры L/S с масштабом 1; при нехватке места разрешены перекрытие и выход крупных объектов за границы холста с обрезкой в редакторе и SVG. Выбранный L не заменяется автоматически на S. Мелкие объекты внутри каждой роли располагаются выше крупных. Размеры исходников и холста передаются модели как метаданные.
- Новые иллюстрации и внутренние контуры объектов не генерируются и не перерисовываются.
- Пропорции сохраняются: масштабирование только одним числом, без независимых `scaleX`/`scaleY`.
- Результат — самостоятельный редактируемый векторный SVG, без `<image>`, `foreignObject`, глобальных `<style>` и внешних ресурсов.
- ИИ самостоятельно определяет роли: допускаются композиции без фоновых объектов, смешанные и полностью фоновые. Общий лимит — 6 объектов; фиксированного лимита числа фоновых объектов нет.
- Пользователь может поправить результат: добавить, переместить, повернуть, масштабировать, продублировать, удалить объект и изменить порядок слоёв.
- Нужны разные форматы композиции, смена встроенной схемы и загрузка пользовательской палитры с перекраской всей сцены.
- Встроенная подготовленная библиотека закрывает исходное требование к источнику иллюстраций. Загрузка собственной библиотеки SVG — дополнительный этап, а не условие первой рабочей версии.

## 2. Уточнения по скриншотам ТЗ

### Детализация каждого объекта L/S и ручной размер

- L и S — два независимо выгруженных SVG с разной детализацией. S нельзя получать уменьшением контуров L и наоборот.
- У выбранного экземпляра есть переключатель «Детализация» L/S (`SceneItem.size`). В одной композиции можно смешивать уровни, включая разные экземпляры одного объекта.
- По последнему уточнению пользователя L/S выбирает реальный размер исходника и связанную детализацию. Начальный масштаб — 1 (100%); S не нормализуется по ширине L. Переключение L/S сбрасывает ручной масштаб до 100%, собственные width/height и viewBox сохраняются.
- Поля «Ширина» и «Высота» показывают размер рамки объекта в единицах SVG-холста. Ввод одной стороны пересчитывает другую через один общий `scale`; подтверждение — Enter или уход из поля. Нулевые, отрицательные, пустые и нечисловые размеры не изменяют сцену.
- Четыре маркера на углах рамки позволяют пропорционально менять размер мышью и пальцем. Противоположный угол остаётся на месте, отрицательный масштаб и схлопывание предотвращаются. Стрелки клавиатуры на маркере также меняют масштаб.
- Ручной ввод сохраняет центр объекта. Угловое масштабирование пересчитывает центр с учётом противоположного неподвижного угла и поворота. Роль main/bg, индивидуальные цвета, детализация и остальные экземпляры сохраняются.
- Рамка и углы — отдельный слой интерфейса; в экспортируемый SVG они не попадают.
- `Scene.width`/`height` задают формат холста; общего `Scene.detailSize` нет. В библиотеке показываем L-превью, новые экземпляры добавляются в L, в списке отображаем детализацию каждого экземпляра.
- Подложка выбирается отдельно через `Scene.canvasId`; её детализация L/S хранится в `Scene.canvasSize` (по умолчанию L). Переключатель использует отдельные исходные SVG для холста и экспорта. Палитра, детализация и масштаб объектов не меняют выбранный фон и его детализацию.
- Размер холста соответствует исходному фону: L — 1000 × 1000, S — 500 × 500. Центры существующих предметов переносятся пропорционально размеру холста, сами предметы не масштабируются.

### Главные и фоновые объекты

- `main` — цветной объект; в нём допустимы цвета объектной и фоновой групп активной схемы.
- `bg` — монохромный объект в оттенках фоновой группы. Монохромность здесь не означает обязательную заливку одним hex.
- В фоновых объектах разрешены только роли `bg1`, `bg2`, `bg3`; объектные роли, `black` и `white` преобразуются по согласованному правилу.
- Подложка холста `canvas1`/`canvas2`/`canvas3` — отдельная сущность. К ней не применяется преобразование объекта в `bg`; её исходные декоративные элементы сохраняются.

### Пользовательские палитры

- Кнопка «Добавить палитру» под текущей схемой открывает модалку с названием, восемью HEX-полями и нативными пикерами. За основу берутся цвета выбранной схемы. До подтверждения сцена не меняется.
- Принимаются HEX из 3 или 6 цифр с # или без него; сохраняются нормализованные #RRGGBB. Все восемь ролей обязательны, название — 1..80 символов. Совпадающие цвета в разных ролях разрешены: сами роли остаются независимыми.
- «Добавить и применить» регистрирует схему в SchemeStore и сразу выбирает её. Холст, main/bg-объекты, загруженные SVG, библиотечные превью, доступные цвета и экспорт перекрашиваются общим рендерером. Геометрия, слои, выделение, детализация, роли и индивидуальные замены сохраняются.
- Пользовательские схемы получают custom-scheme-* ID и не связаны с шаблоном подложки. Их можно переключать вместе со встроенными. SceneStore проверяет принадлежность схемы текущему реестру до изменения сцены.
- Схемы существуют только в памяти вкладки. После перезагрузки остаются три встроенные; сервер, localStorage, sessionStorage и IndexedDB не используются. Встроенные JSON и исходные SVG не меняются.
- Отмена, Escape, крестик и клик по затемнению закрывают окно без применения. Нативный dialog блокирует фоновые элементы; фокус возвращается кнопке открытия. На мобильной ширине содержимое модалки прокручивается внутри экрана.

### Пользовательские SVG

- Кнопка «Загрузить SVG» сразу добавляет проверенный файл до 2 МБ в библиотеку с названием из имени файла. Ручного назначения цветов и промежуточной формы нет. По последнему запросу пользователя роли подбираются автоматически: точные совпадения с активной схемой сохраняются, чёрный/белый остаются нейтральными, остальные цвета сопоставляются с ближайшими свободными цветными ролями. Разные исходные цвета сохраняют независимые роли, пока хватает шести цветных ролей; лишние объединяются с ближайшими оттенками, с сообщением после импорта. Повторы одного нормализованного hex, включая разные записи RGB/HEX/имя, считаются одним цветом. Порядок контуров не влияет на результат.
- Служебные объявления xmlns:c2pa и других дополнительных пространств имён, metadata/RDF, title/desc, Inkscape/Sodipodi-поля, data-/aria-атрибуты и классы удаляются из импортируемой копии. Они не вызывают ложный отказ; исходный файл не изменяется. XML base, SVG/XLink-атрибуты, скрипты и внешние ссылки остаются под строгой проверкой.
- Допускается статическая геометрия SVG с внутренними clipPath. Скрипты, обработчики событий, внешние ресурсы, растр, глобальные стили, текст, градиенты, фильтры и use отклоняются до вставки в DOM с понятной ошибкой. Inline presentation-стили преобразуются в атрибуты; цвета нормализуются.
- LibraryStore держит расширенный каталог и манифест только в памяти вкладки. После перезагрузки загруженные объекты исчезают; сервер, база и браузерное хранилище для импорта не используются. Исходные папки и встроенный манифест не изменяются.
- Импортированный SVG — самостоятельный L-ассет; S недоступен без отдельного исходника. Новая иллюстрация сохраняет размер исходного viewport (width/height), контуры, viewBox и пропорции; начальный масштаб равен 1. Все обычные операции и SVG-экспорт работают через общий рендерер.
- Проверка регистрации и доступной детализации происходит до изменения сцены. ID пользовательских объектов имеют отдельный префикс custom-; определения получают уникальные префиксы в превью и каждом экземпляре.

### Индивидуальные цвета объектов

- Скриншот с примерами прямо разрешает менять цвета объекта в пределах выбранной схемы; один и тот же кошелёк может быть фиолетовым или жёлтым в одной композиции.
- В панели выбранного экземпляра пользователь выбирает используемый цветовой участок и новый оттенок из активной палитры. Изменение применяется ко всем контурам с этой исходной ролью; геометрия сохраняется.
- В `main` доступны шесть цветных ролей `bg1..bg3`, `obj1..obj3`; чёрные и белые детали остаются исходными. В `bg` доступны только `bg1..bg3`.
- Настройки каждого экземпляра хранятся в `colorOverrides.main/bg` как роли, без конкретных hex. Цвета главного и фонового вариантов независимы и восстанавливаются при переключении роли.
- Смена общей схемы и L/S сохраняет настройки. Отсутствующий в другом размере цветовой участок не выводится из геометрии соседнего варианта.
- Замены выполняются одновременно, одним применением к исходной роли. Сброс возвращает цвета только текущего main/bg-варианта выбранного экземпляра. Подложка и остальные экземпляры не меняются.

### Выбор объекта на холсте

- Выбор и начало перетаскивания работают по всей прямоугольной рамке исходного viewBox, включая пустые и прозрачные участки SVG. Повторные клики внутри выбранного объекта сохраняют возможность его двигать.
- В точке пересечения рамок выбирается верхний объект по актуальному порядку Scene.items. Прозрачная область верхнего SVG также перекрывает нижний объект для выбора.
- Проверка использует getObjectGeometry и обратный поворот вокруг центра: учитывает активный L/S, единый масштаб и собственные пропорции, включая смещённый viewBox пользовательских SVG. Вне повёрнутой рамки и за пределами холста объект не выбирается.
- Над доступной областью курсор показывает возможность перемещения. Углы масштабирования и быстрые кнопки слоёв сохраняют собственное действие. Клик по свободному холсту снимает выделение.
- Выбор выполняется чистой геометрической функцией; дополнительные контуры для кликов в SVG не добавляются, экранная композиция и экспорт используют прежний рендерер.

### Поворот объектов

- Над рамкой выбранного объекта и в правой панели есть две стрелки: по часовой и против часовой. Шаг задаёт общая константа ROTATION_STEP = 15°, справа отображается текущий угол.
- rotateSceneItem — чистая функция относительного вращения; SceneStore.rotateSelected вызывает её только для выделенного экземпляра. Угол нормализуется в диапазон 0..359°, полный оборот возвращает исходное положение.
- Поворот сохраняет центр, единый масштаб, детализацию, роли, индивидуальные цвета и порядок слоёв. Рамка, определение попадания указателя, перетаскивание и угловое масштабирование учитывают угол. При resize противоположный угол остаётся неподвижным.
- Быстрые кнопки сохраняют выделение и не запускают drag; панель помещается в холсте на desktop/mobile. Экспорт содержит исходные векторные контуры и transform rotate, без элементов управления.

### Порядок слоёв

- `Scene.items` хранит объекты снизу вверх; их номер слоя равен индексу плюс 1. Подложка всегда рисуется перед объектами и не участвует в перестановке.
- Список «Слои» показывает обратный порядок: верхняя строка — верхний объект, число больше — слой выше. Отдельного дублирующего `zIndex` в модели нет.
- Слой можно перетаскивать за значок слева мышью или пальцем. Есть маркер вставки, автопрокрутка длинного списка, перестановка стрелками клавиатуры, отмена через Escape/pointercancel.
- Над рамкой выделения находятся быстрые кнопки «На слой выше»/«На слой ниже» и текущий номер. На границах соответствующая кнопка недоступна.
- В настройках выбранного объекта поле «Порядок слоя» позволяет задать целое число от 1 до количества объектов. Неверный ввод сохраняет прежний порядок.
- Перестановка сохраняет выделение, геометрию, детализацию, роль, индивидуальные цвета, подложку и палитру. Новый объект добавляется сверху, удаление уплотняет номера.
- Экспорт использует тот же порядок SVG-элементов; рамка, стрелки и прочие элементы интерфейса не экспортируются.

## 3. Что уже сделано

- Каркас Vite + React + TypeScript strict, ESLint, Prettier и Vitest.
- Структура `src/domain`, `src/services/{svg,layout,ai}`, `src/stores`, `src/ui`, `scripts`, `api`.
- Рабочий интерфейс: каталог с превью и добавлением, SVG-холст, выбор экземпляра по всей SVG-рамке/списком с приоритетом верхнего слоя, детализация L/S каждого экземпляра, ручной ввод размеров, масштабирование за угол и общая палитра, отдельный выбор фона, main/bg выбранного объекта, индивидуальная замена цветов и сброс, список слоёв с перетаскиванием и номерами, быстрые стрелки порядка над рамкой, перетаскивание мышью/пальцем, поворот стрелками над объектом и справа, удаление выбранного экземпляра, скачивание SVG. На широком экране панели прокручиваются внутри редактора, не сдвигая холст.
- Чистая модель сцены, MobX-стор и общий renderer для превью, экрана и экспорта.
- Манифест загружается отдельным статическим JSON; есть состояния загрузки, ошибки и повтор запроса. Пользовательские SVG добавляются через безопасный импорт и временный LibraryStore, с автоматическим назначением цветовых ролей и сохранением пропорций.
- 26 SVG скопированы в `src/assets/library` с именами `<id>__<L|S>.svg`: 10 объектов × 2 размера и 3 подложки × 2 размера.
- Опечатка `Кнгига-S.svg` исправлена только в имени копии: `book__S.svg`.
- `schemes.json`, отдельные карты исходных цветов в `color-map.json`, пустые `tags.json` для всех 13 id.
- `normalizeColor`, `prepareSvg`, `prefixSvgIds`, `toBackgroundVariant`, сборка `manifest.json` командой `build:library`.
- Манифест содержит отдельно подготовленные L/S; у объектов есть `svg` и `backgroundSvg`.
- Последняя выполненная проверка: 761 тест Vitest, 44 браузерных сценария Playwright в Chrome, `build:library`, `build` и `lint` проходят. Проверены desktop/mobile, независимая детализация L/S и смешанные сцены, стандартный размер, ввод ширины/высоты и угловое масштабирование мышью/пальцем без искажения пропорций, внутренняя прокрутка панелей без сдвига холста, все девять сочетаний независимо выбранных фона и палитры, слои через drag/число/быстрые стрелки/клавиатуру, реальное перекрытие и порядок SVG, независимая перекраска экземпляров, раздельные цвета main/bg и их сброс, повторные вставки, выбор и drag за пустую область SVG, приоритет прозрачной области верхнего слоя и его изменение после перестановки, вращение в обе стороны и полный оборот, move/resize при 45° с сохранением противоположного угла, перемещение, удаление, загрузка и экспорт. Дополнительно проверены автоматический импорт пользовательских SVG без формы назначения ролей, объединение одинаковых цветов из HEX/RGB/имён, независимость результата от порядка контуров, роли цветов, отклонение небезопасных файлов до вставки в DOM, nonzero viewBox, единственный L, независимые экземпляры, повторная загрузка после ошибок и сброс библиотеки после обновления страницы. Проверены модалка палитры, ввод HEX/пикеры, перекраска всех групп и превью/экспорта, отмена и клавиатура, мобильная прокрутка, переключение и сброс пользовательских схем без записи в Storage/API. Ручная проверка редактируемости в Figma и точная сверка всех фоновых вариантов ещё нужны.
- Исходные папки `allPictures` и `colors bg-object by bg` сохранены; при копировании проверены SHA-256 оригиналов и копий. Их не менять и не удалять.

Пока не реализованы дублирование объектов, автоматическая раскладка, смысловой подбор и серверная функция. Теги намеренно остаются пустыми до отдельного этапа описания каталога.

| Ручка          | `pen`        |
| Телефон        | `phone`      |

Подложки: `canvas1`, `canvas2`, `canvas3`. Таким образом, текущие 20 объектных иллюстраций — это 10 типов в вариантах L/S; подложки учитываются отдельно. Скриншоты подтверждают устройство каталога из двух наборов детализации.

### Палитры

Роли строго соответствуют ячейкам исходных палитр:

- Левая колонка сверху вниз: `bg1`, `bg2`, `bg3`, `black`.
- Правая колонка сверху вниз: `obj1`, `obj2`, `obj3`, `white`.
- В исходных схемах `black` — `#181817`, `white` — `#FFFFFF`.
- `#000000` — обводка белой ячейки SVG палитры; отдельной роли у неё нет.

| Исходная схема | Исходная подложка | bg1       |
| -------------- | ----------------- | --------- |
| `purple`       | `canvas1`         | `#D7CDF5` |
| `orange`       | `canvas2`         | `#FDD7B9` |
| `teal`         | `canvas3`         | `#BEEBEB` |

Разделяем исходную схему ассета и активную схему сцены:

1. При подготовке все 10 объектов и `canvas1` используют карту `purple`; `canvas2` — `orange`; `canvas3` — `teal`.
2. Исходные цвета нормализуются и превращаются в роли через карту только своей исходной схемы. Глобальная таблица hex → роль запрещена.
3. Подготовленный SVG содержит токены вида `var(--obj1)`.
4. При отображении и экспорте роли заменяются конкретными hex активной схемы. Повторно определять роль через цвет активной схемы нельзя.
5. Подложка выбирается через `Scene.canvasId` независимо от активной схемы. Все элементы сцены и выбранная подложка перекрашиваются одновременно. Необязательное поле `ColorScheme.canvas` сохраняет исходное соответствие встроенной палитры и подложки и не управляет текущим выбором фона; у пользовательских схем его нет.

Межсхемные совпадения допустимы: `#80DADA` — `orange.obj2` и `teal.bg2`; `#BEEBEB` — `orange.obj3` и `teal.bg1`. Раздельные исходные карты устраняют неоднозначность.

Реестр SchemeStore поддерживает три встроенные и произвольное число пользовательских схем в текущей вкладке. SchemeId расширен отдельным пространством custom-scheme-*, встроенные исходные карты и build:library сохраняют строгий набор из трёх схем.

### Фоновый вариант объекта

Применяется реализованное правило:

| Исходная роль                   | Роль в bg     |
| ------------------------------- | ------------- |
| `black`                         | `bg3`         |
| `obj1`, `obj2`, `obj3`, `white` | `bg1`         |
| `bg1`, `bg2`, `bg3`             | без изменений |

TODO: правило сохранения `bg2` на объекте `vase` ещё не подтверждено визуальной сверкой с исходным фоновым вариантом Figma. Скриншот показывает ожидаемое устройство фоновых объектов, но не даёт основания менять точный hex или преобразование контуров. До проверки сохраняем текущую реализацию и предупреждение сборки.

### Определения, ID и экспорт

- `prepareSvg` обрабатывает `fill`/`stroke`, нормализует hex, `white`/`black` и `rgb()`.
- Цвета внутри `defs` и `clipPath` не заменяются ролями. Например, служебный белый прямоугольник в `canvas2` остаётся белым.
- Каждая вставка получает уникальный идентификатор экземпляра. `prefixSvgIds` префиксует ID и обновляет ссылки на определения, включая `url(#...)`, `href` и `xlink:href`.
- Повторная вставка одного ассета и использование нескольких клипов не должны создавать коллизий.
- Подготовку исходника, применение активной схемы и создание экземпляра сцены разделяем на отдельные операции.
- Для экрана и скачивания используем общий код сборки композиции. Экспорт содержит конкретные цвета, все необходимые определения и векторные трансформации; не содержит неразрешённых токенов `var(...)`.
- Составные контуры и определения сохраняются; для редактируемости экспорт проверяется открытием в Figma. Illustrator — дополнительная проверка при доступности.

## 5. Архитектура следующего этапа

### Стек и ответственность

- Установлены Vite, React, TypeScript strict, Vitest, `@xmldom/xmldom`, `tsx`, MobX, `mobx-react-lite` и Playwright.
- Палитры проверяются чистыми функциями createCustomScheme/normalizeSchemeColor. zod подключаем для проверки ответов ИИ на соответствующем этапе.
- `src/domain`: чистые модели и правила сцены, цвета, трансформации, форматы, проверка допустимости операций. Без React и MobX; с тестами.
- `src/services/svg`: подготовка SVG, применение схемы, создание экземпляров и сборка/экспорт сцены.
- `src/services/layout`: детерминированная автоматическая раскладка.
- `src/services/ai`: поиск компонентов, клиент серверной функции, проверка ответов.
- `src/stores`: состояние и действия MobX; бизнес-правила вызываются из чистых функций.
- `src/ui`: библиотека, SVG-холст и панели настроек.
- `/api/compose.ts`: единственная serverless-функция для смыслового подбора; ключ API хранится на сервере.

Холст строим на inline SVG. Оптимизацию SVG и дополнительные библиотеки трансформаций подключаем только при конкретной необходимости; не изменяем контуры ради оптимизации.

### Планируемая модель сцены

- `Scene`: формат и `width`/`height`, активная схема `schemeId`, независимо выбранная подложка `canvasId`, упорядоченные элементы; общего размера объектов нет.
- `SceneItem`: уникальный id экземпляра, `assetId` объекта, собственный `size: L | S`, роль `main`/`bg`, позиция, один `scale` относительно ширины L (по умолчанию 0.35), поворот, допустимые переопределения цветовых ролей.
- Детализация ассета разрешается через `SceneItem.size`; собственные рамки и контуры сохраняются, а общий видимый размер рассчитывается `getObjectGeometry` через размеры выбранного исходника и один ручной `scale`. Эта функция используется рендерером, числовыми полями и рамкой выделения.
- Переопределения цвета хранятся через роли активной схемы, чтобы сохранялась корректная перекраска при её смене. В `bg` разрешается выбрать только фоновую группу.
- Порядок элементов определяет слои. `setSceneItemLayer` переставляет только массив, сохраняя ссылки объектов; `getSceneItemLayer` возвращает номер 1..N. Store и UI используют эти чистые функции.
- Выделение и состояния жестов относятся к редактору, а не к экспортируемой геометрии.

Начать с минимального набора сторов для каталога, реестра схем и сцены. Состояние ИИ и история undo/redo добавляются по мере реализации соответствующих этапов; отдельный стор для чистой сериализации SVG не требуется.

## 6. Порядок реализации и критерии приёмки

### Этап 1 — рабочая SVG-сцена

Статус: техническая часть реализована. Автоматические проверки и просмотр desktop/mobile пройдены; ручная сверка экспорта в Figma и `vase.bg2` остаются открытыми.

Результат: библиотека → добавление объекта → смена схемы/детализации → скачивание SVG.

1. Добавить чистую модель сцены и функции операций, затем подключить MobX.
2. Загрузить существующий манифест и схемы; показать превью и названия 10 объектов слева.
3. Отобразить квадратную подложку и добавляемые экземпляры на настоящем SVG-холсте.
4. Добавить детализацию L/S выбранного объекта со стандартным видимым размером, общий выбор схемы и main/bg экземпляра. Подложку выбирать отдельно от объектного каталога.
5. Реализовать общий материализатор сцены: роли → конкретные цвета, уникальные ID, корректные трансформации.
6. Добавить минимальное скачивание результата в SVG.

Приёмка:

- Все 26 независимых ассетов отображаются; состав и роли не теряются при смене L/S.
- Смена схемы перекрашивает всю композицию, сохраняя выбранную подложку. Отдельная смена подложки сохраняет палитру, выделение, состав, геометрию и индивидуальные цвета объектов. Все девять сочетаний трёх подложек и трёх схем поддерживаются.
- Главные и фоновые варианты визуально сверены с доступными референсами; неподтверждённый `vase.bg2` отмечен отдельно.
- Геометрия не искажается; две вставки одного SVG не конфликтуют по ID.
- Скачанный SVG открывается в Figma, содержит векторные элементы и конкретные hex, соответствует изображению на экране.
- Чистые функции покрыты тестами; существующие проверки проходят.

### Этап 2 — автоматическая композиция по названиям

Автоматизацию делаем рано, до расширенного ручного редактора.

1. Добавить названия и поиск по существующим компонентам; неизвестные названия показывать пользователю, не придумывая новые объекты.
2. Определить точные форматы: квадрат, горизонтальная и вертикальная композиции; зафиксировать правило размещения квадратной подложки в прямоугольнике. Масштаб только равномерный, обрезка — явным клипом, без растягивания.
3. Реализовать раскладку чистыми функциями: шаблоны под количество и форму объектов, нормализованные позиции, допустимые пересечения, поля, порядок слоёв и фоновая группа.
4. Добавить seed и кнопку «Другой вариант». Допустить отсутствие фоновых объектов.
5. Добавить переключение формата с повторной компоновкой выбранных компонентов.

Приёмка: работает второй сценарий ТЗ, одинаковые входные данные и seed воспроизводят результат; главные объекты читаются, нет непреднамеренной обрезки, оба набора детализации и все схемы работают без искажений. Качество раскладок проверяется на 2–3 композициях, а не только тестами координат.

### Этап 3 — редактор и загрузка палитры

1. Выделение, перетаскивание мышью/пальцем и удаление выбранного экземпляра уже доступны. Равномерный масштаб через поля и углы реализован. Порядок слоёв через список, стрелки над рамкой и числовое поле реализован. Поворот по 15° стрелками над объектом и в настройках реализован. Добавить дублирование; при необходимости — undo/redo.
2. Выбор цвета через разрешённые роли схемы реализован: независимые экземпляры, раздельные main/bg-настройки, сброс, сохранение при смене схемы и L/S; запрет объектных цветов для `bg` сохраняется.
3. Создание палитры реализовано модалкой с восемью HEX-полями и пикерами. Импорт JSON/SVG-ячеек не входит в текущий запрос и остаётся возможным расширением.
4. Проверяются полнота восьми ролей, название и корректность HEX3/HEX6; регистр и короткая запись нормализуются. Применение новой схемы сохраняет независимо выбранный шаблон подложки.
5. Схема добавляется в расширяемый реестр SchemeStore и сразу перекрашивает всю композицию, сохраняя геометрию и роли. Реестр хранится только в памяти и сбрасывается после перезагрузки.

Приёмка: пользователь редактирует автоматически собранную композицию и применяет новую палитру ко всем элементам; экран и экспорт совпадают. Неполные или неверные данные показывают понятную ошибку, без частичного повреждения сцены.

### Этап 4 — метафора или заголовок

1. Отдельной задачей описать каталог: добавить теги и русские/английские синонимы в текущую пустую заготовку. Подложки не включать в список объектов для смыслового подбора.
2. Реализовать локальный подбор по названиям и тегам как базовый режим; явно сообщать об отсутствии совпадений.
3. `/api/compose.ts` передаёт ИИ каталог с доступными L/S и текст запроса; принимает только разрешённые id объектов, роли `main`/`bg` и выбранную детализацию. Недоступный вариант отклоняется; старые планы без детализации получают L.
4. Проверять ответ через zod и каталог. Не использовать неизвестные id, SVG, координаты, произвольные цвета или другие неподдерживаемые поля из ответа.
5. Раскладка использует выбранные моделью роли и детализацию, сохраняя пропорции каждого исходного SVG. Выбранный фон, его детализация, формат и палитра сцены сохраняются.
6. Обработать загрузку, сетевые ошибки и отсутствие API-ключа. Локальный поиск не выдавать за полноценное понимание любой метафоры.

Приёмка: работают оба сценария исходного задания, ИИ не создаёт графику и не определяет геометрию; ошибочный ответ не повреждает композицию; ключ недоступен в браузере.

### Этап 5 — проверка и сдача

- Playwright: выбор компонентов → композиция → смена L/S → смена/загрузка палитры → правка → экспорт; отдельно проверить сценарий метафоры и ошибки.
- Регрессии SVG: клипы и повторные экземпляры, сохранение пропорций, разрешённые роли, отсутствие растра и неразрешённых токенов.
- Визуальная сверка main/bg, обоих размеров и всех трёх встроенных схем с референсами.
- Проверка редактируемости экспортов в Figma.
- Публикация рабочего сервиса с серверной функцией, проверка ссылки и доступа к исходникам.
- README: запуск, конфигурация, хранение/извлечение/повторное использование SVG, описание алгоритма композиции и ограничений.
- Список использованных ИИ-инструментов и 2–3 примера композиций в SVG с короткой демонстрацией.

## 7. Открытые вопросы и отложенная работа

- Визуально подтвердить правило `bg2` для фоновой вазы по исходному компоненту Figma; до этого не менять согласованное преобразование.
- Определить точные дополнительные форматы и кадрирование подложек. Размеры фреймов каталога не использовать вместо размеров композиций.
- При визуальной проверке подтвердить детализацию каждой пары L/S и стандартный видимый размер, включая смешанные сцены; не подменять независимые контуры масштабированием одного варианта и не искажать пропорции.
- Перед подключением ИИ выбрать доступный серверный провайдер и место хранения ключа; перед публикацией — хостинг с поддержкой одной serverless-функции.
- Одиночный импорт статических пользовательских SVG реализован по отдельному запросу пользователя. Пакетный импорт библиотеки/zip, дополнительные пары L/S и расширенные SVG-возможности остаются отложенными. Пользователь явно разрешил автоматический подбор ролей при импорте SVG; он реализован отдельно от строгих исходных карт встроенной библиотеки. Палитра-источник выбирается только текущая, глобальные карты между схемами не используются.

## 8. Команды и порядок работы

- `npm run dev` — локальный запуск.
- `npm run build:library` — сборка манифеста из копий SVG, с предупреждениями; исходные папки не меняются.
- `npm run build` — актуализация манифеста, проверка TypeScript и production-сборка.
- `npm test` — Vitest.
- `npm run test:e2e` — браузерные сценарии Playwright с автоматическим запуском и остановкой Vite.
- `npm run lint` — ESLint и Prettier.

Для первого запуска Playwright установить Chromium командой `npx playwright install chromium`. Можно использовать установленный Chrome: в PowerShell `$env:PLAYWRIGHT_CHANNEL = 'chrome'`, затем `npm run test:e2e`. Для браузерной проверки текущего этапа использован установленный Chrome.

Работать по одному этапу с его критериями приёмки: сначала чистые функции и содержательные тесты, затем состояние и UI. Не считать подготовленную библиотеку готовым конструктором. Предупреждения сборки и неподтверждённые визуальные правила сохранять видимыми до их проверки.
